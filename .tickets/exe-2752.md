# Topology records (Vertex, HalfEdge, Face)

Define the core topology record structs that live inside arenas. These are the raw data that the half-edge mesh is built from.

## Design

Vertex { out: HalfEdgeId }
  - out: one outgoing half-edge, or a sentinel if isolated

HalfEdge { to: VertexId, face: FaceId, next: HalfEdgeId, twin: HalfEdgeId }
  - to: destination vertex
  - face: owning face (FaceId::OUTSIDE for boundary)
  - next: next half-edge in face loop
  - twin: opposite half-edge (always valid per boundary model)

Face { edge: HalfEdgeId, degree: u32 }
  - edge: one half-edge in the face loop
  - degree: cached loop length (optional but useful)

All fields use stable IDs. No Options in hot fields — sentinels instead (per "Explicit Over Implicit" tenet). All structs are Copy + Clone + Debug.

## Acceptance Criteria

- Vertex, HalfEdge, Face structs defined with correct fields
- All fields use the ID types from exe-dc9l
- No Option types in hot fields (sentinels instead)
- All structs are Copy + Clone + Debug
- Structs are well-documented

**2026-03-03 — prev pointer decision**

HalfEdge will NOT store a prev field in v0.1. prev(h) is derived by walking the face loop (next chain). This saves 4–8 bytes per half-edge and simplifies mutation. See exe-ei01 for the decision ticket. If profiling shows prev traversal is a bottleneck, a stored prev pointer can be added later.
